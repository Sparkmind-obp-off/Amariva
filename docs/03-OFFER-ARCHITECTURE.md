# AMARIVA — OFFER ARCHITECTURE

## Offer Ladder

AMARIVA should have a visible progression from free utility to paid depth.

```
FREE
↓
LOW-RISK PAID
↓
CORE PRODUCT
↓
RECURRING SOFTWARE
↓
HIGH-VALUE SOLUTION
```

## 1. Free

Examples:

- calculators,
- generators,
- checklists,
- scorecards,
- estimators,
- planners,
- simple diagnostics.

Purpose:

**capture intent and create a useful first experience.**

## 2. Entry Product

Examples:

- template packs,
- operational kits,
- playbooks,
- compact guides,
- ready-to-use spreadsheets.

Purpose:

**convert trust into the first transaction.**

## 3. Core Product

Examples:

- complete operating systems,
- workflow products,
- packaged business kits,
- specialized software.

Purpose:

**solve a meaningful recurring problem.**

## 4. Recurring Product

Examples:

- SaaS,
- monitoring,
- recurring reports,
- ongoing automation,
- maintained libraries,
- subscription utilities.

Purpose:

**create predictable recurring revenue.**

## 5. Higher-Value Solutions

Only after repeatable demand exists.

Examples:

- implementation packages,
- migration,
- setup,
- custom configuration around a standardized core product.

Avoid returning to one-off custom projects as the dominant model.

## Offer Design Rule

Every paid offer must answer:

- What problem does it solve?
- What changes after purchase?
- How quickly can the buyer reach value?
- What is included?
- What is not included?
- Why buy instead of doing it manually?
- What proof exists?

## Pricing Principle

Do not begin with “what can we charge?”

Begin with:

**Outcome → complexity → time saved → risk reduced → value created → willingness to pay.**

Then choose a price that supports healthy conversion and margin.

## Offer Naming

Use clear product names under AMARIVA.

Avoid:

- confusing SKU names,
- meaningless feature bundles,
- too many tiers,
- “enterprise” language for tiny products.

## Conversion Rule

One page should have:

**one primary problem + one primary offer + one primary CTA.**

Cross-sells can exist, but they must not obscure the main decision.
